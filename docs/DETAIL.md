# 会话状态筛选

在左侧工作区工具栏下方加一排状态 chip，点击即按状态筛选会话：

- **全部** —— 关闭筛选，恢复官方列表
- **运行中** —— 该会话的 agent 正在执行（Host 判定 `agent.status === 'running'`）
- **待确认** —— 会话在等你操作：审批（approval）、计划审查（plan-review）或提问（question）
- **未读** —— 后台跑完、而当时你不在看它；切回该会话即视为已读（官方语义）

每个 chip 带实时计数；每行会话右侧还有一个小圆点徽标（绿=运行中、橙=待确认、蓝=未读，多状态叠加为双色点）。

## 用法

1. 刷新 DSH 页面后，左侧工作区工具栏（「全部对话 / 工作区」那一行）下方出现 chip 排
2. 点任意状态 chip → 下方直接列出该状态下的全部会话（工作区名 · 标题 · 时间），点击条目打开会话
3. 再点同一个 chip，或点「全部」→ 关闭筛选、恢复官方列表

## 为什么是自绘列表

官方侧边栏对**折叠的工作区**和**组内“显示更多”**不渲染会话行，第三方插件无法用 CSS 让它们出现。
因此筛选结果由本插件自行渲染，保证「数字 = 能看到的结果条数」；筛选期间隐藏官方列表，避免同屏两套。

## 数据来源

| 状态 | 来源 |
|---|---|
| 运行中 | `ctx.sessions.list` 的 `running` 字段 + `uiSession.sessionStatus` |
| 待确认 | `uiSession.sessionStatus.pendingInteraction`（只信 UI 注册的挂起交互，回答后立刻清除） |
| 未读 | `uiSession.sessionStatus.completionUnread` |

不写入任何会话状态，只读官方服务；卸载插件即完全恢复。

## 已知限制

- 「未读」遵循官方语义：完成时你不在看它才算未读，切回该会话即清零
- 已归档会话不出现在筛选结果里（与官方列表一致）
- 子代理（subagent）会话被排除，它们本来就不显示在侧边栏
- 筛选激活时官方列表被隐藏，关闭筛选后恢复

## 卸载

在插件管理里禁用或移除本 bundle 即可，无残留数据。
